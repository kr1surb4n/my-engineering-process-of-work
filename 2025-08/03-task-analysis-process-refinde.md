# Project Adventure: Refined Task Analysis Process

## 1. Project Brainstorm
This is the area to define the scope. The goal is to move the "pain" of the project to the beginning, where it is cheaper to fix.

**The Core Philosophy:**
Coding is a translation task. If you can describe the project perfectly in plain English, the actual programming is simply translating that English into a technical dialect.

**Guidelines:**
- Use simple, plain English. Avoid jargon.
- Thinking in human language is more intuitive than thinking in programming logic.
- Aim for a "Full Description" before implementation to avoid late-stage discoveries that cause rework and missed deadlines.

### 1.1 The Vision (The "What")
Describe the goal from the highest level of abstraction.
- **Starting Point:** What exists (or doesn't exist) at the beginning?
- **Ending Point:** What does the final state look like?
- **The Deliverable:** What is the tangible result?
- **Conceptual Model:** Can you represent the logic using plain text files or simple diagrams?

### 1.3 Implementation Strategy (The "How")
**Technical Foundation:**
- **Tech Stack:** Which languages, frameworks, or libraries? Why these?
- **Environment:** Where will this exist? What are the OS/hardware constraints?

**System Architecture:**
- **Elements:** What are the core components?
- **Properties:** What are the attributes of these elements?
- **Behaviors:** How do these elements interact?
- **Requirements:** What *must* it do to be considered successful?
- **Constraints:** What *must not* happen?

**Data Flow:**
- **Inputs/Outputs:** Define exactly what goes in and what comes out.
- **Fixtures:** Create sample data/input files to test assumptions.

### 1.4 The Stress Test (Verification)
Define how to prove the system works. Don't just test the "happy path."
- **Positive Testing:** What should it do correctly?
- **Negative Testing:** How do you know it's actually working (and not just appearing to)?
- **Edge Cases:** 
    - How to break it?
    - What happens with "bad" input?
    - What happens at the absolute limits of its capacity?
    - What happens if the input is misleading or "lies"?
    - What is the "heart" of the system, and what happens if it's removed?
