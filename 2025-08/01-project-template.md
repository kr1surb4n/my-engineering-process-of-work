# Project Adventure

## Project Brainstorm
Brainstorming area where you define the scope of the project.

Avoid jargon as much as you can. Use simple plain English. 

Thinking in Human Language is easier for you, than thinking in Programming Language. 

Don't start before you won't have the full description. 
Yeah, I know it looks like a lot of work. Just trust me.
You don't want to find out that someone you're working with
has no idea what is doing, and a week before the deadline you discover that he:Define
- told you something that makes no sens and you finaly see that today 
- didn't told you something important what you need and will take 2 weeks to get
- gave you wrong things and you have to rework everything
etc.
You want to find issues sooner, not later. 

With full description, coding task changes into a translation task
from English to a Nerd-English dialect. It's a lot easier work. 

Plus, you can send the description for a review now. 

### What do you want to make?
In simple words describe here what you want to do. 
Start from the highest perspective/abstraction level. 
What is in the begining?
What is in the end?
What is the result?
Can you make a simple models using plain text files?

### What do you know?
List what you know. Use a list. 

### What you don't know?
List the things you don't know. Write them as questions. 
Update this list. When you will have the answers, prune this list
by moving it to the section above.

i.e. 
- How do I read a text file in python 3?
- How do I start a project in Scala?

### How are you going to do it?
How it will be build?
What elements it has?
What are the properties of those elements?
What constrains are there?
What are the requirements?
   
Describe the environment in which you thing will exist. 
Define the structure, behaviors, requirements, constrains,
elements. Repeat for the elements and behaviors.  
Write down the inputs/outputs. Create fixtures. 
Create models that will test your assumptions.
Write how you are going to test this thing and it elements. 
- What should they do right?
- How you know it is working?
- Can you break them?
- Give them bad stuff.
- Break their limits.
- Lie to them. 
- Remove their hearts and see what happens.  
Write down the instructions on how to use the things you're going to create.happens
Write down the steps required to build that thing.
